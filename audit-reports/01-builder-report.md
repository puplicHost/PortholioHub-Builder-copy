# تقرير التدقيق العميق — سطح البنّاء (Builder)

> نوع التدقيق: قراءة فقط (READ-ONLY). لا تعديل على المشروع. كل بند مدعوم بمرجع `ملف:سطر`.
> مستويات الثقة: **مؤكد (Confirmed)** = قرأت الكود بالكامل وترابطه · **مرجّح (Likely)** = الدليل قوي لكن يحتاج تحققًا وقت التشغيل · **مشتبه (Suspected)** = دليل جزئي.
> مستوى الخطورة: Critical / High / Medium / Low. مجال التأثير: يمنع المستخدم / يُبطئ المستخدم / خسارة عمل / أمن / صقل.

## 1) الملخص التنفيذي

سطح البنّاء هو جوهر المنتج: مستخدم (غالبًا عربي، غير تقني، وقد يكون عمره 17 سنة) يبني بورتفوليو ويحفظه وينشره. آلية العمل الحالية تعمل وظيفيًا، لكنها تحمل **ثغرة أمنية حرجة واحدة (IDOR)**، و**ثغرة XSS محتملة (High)**، ومشاكل تجربة تؤدي **لخسارة عمل المستخدم** (لا حفظ تلقائي)، إضافة إلى ملف واجهة ضخم (3586 سطرًا) يزيد صعوبة الصيانة.

- 🔴 **حرجة:** انعدام فحص الملكية في تعديل/حذف صفحات المشاريع → أي مستخدم مسجّل يمكنه العبث بمشاريع غيره.
- 🟠 **عالية:** مسار XSS مخزّن محتمل عبر روابط المشاريع (تُكتب وتُعرض دون تعقيم).
- 🟠 **عالية (تجربة):** لا يوجد حفظ تلقائي؛ الحفظ يدوي فقط.

## 3) المشاكل المرصودة

### 🔴 حرجة — IDOR: لا فحص ملكية عند تعديل/حذف صفحات المشاريع (أمن)
**المؤكد.** داخل `updateProjectPage` و`deleteProjectPage` يتم التحقق من الهوية فقط عبر `requireUserWithWorkspace()` دون التحقق أن الصفحة تخص المستخدم الحالي:

- `portfolio.ts:723` → `const user = await requireUserWithWorkspace()`
- `portfolio.ts:727-730` → `prisma.projectPage.update({ where: { id }, data: pageData })` — بلا شرط `userId`.
- `portfolio.ts:773` → `prisma.projectPage.delete({ where: { id } })` — بلا شرط `userId`.

وأي مستخدم مسجّل يمكنه استدعاء Server Action مباشرة بقيمة `id` تعسّفية. **الأثر:** تعديل/حذف صفحات مشاريع أي مستخدم آخر (مقارنةً بـ`updatePortfolio` الذي يستخدم `where: { userId: user.id }` صحيح).
**الإصلاح:** إضافة شرط الملكية: `where: { id, profile: { userId: user.id } }` قبل أي `update/delete`، والتحقق من النتيجة.

### 🟠 عالية — XSS محتمل عبر روابط المشاريع (أمن)
**مؤكد (مسار البيانات) / مرجّح (الاستغلال).**
- `updateProjectPage` تكتب `externalUrl` خام دون أي schema (`portfolio.ts:741`).
- العرض العام يضعها كـ`href` مباشرة دون تعقيم: `ProjectPageView.tsx:162` و`ProjectPageView.tsx:188`.
- المقابل: `portfolio-schema.ts:37-38` يمنع `javascript:` لـ`projects` فقط، لكنه **لا يُطبَّق** على بنود `projectPage`.

**الأثر:** قيمة `externalUrl = "javascript:..."` تُنتج رابطًا قابلًا للتنفيذ على صفحة عامة (XSS/clickjacking لزوار ملف المستخدم). البِكس `target="_blank"` يخفّض الاحتمالية في بعض المتصفحات لكن المخاطرة قائمة.
**الإصلاح:** تمرير بنود `projectPage` عبر نفس `validateProjects`/دالة `url` (تقبل `https/http/mailto/tel` أو مسار داخلي فقط).

### 🟠 عالية (تجربة/خسارة عمل) — لا يوجد حفظ تلقائي
**المؤكد.** لا توجد أي `setInterval`/debounce للحفظ؛ الحفظ يدوي بالكامل (`handleSaveChanges` عند `BuilderClient.tsx:801`، والزر عند `:3567`). الحماية الوحيدة من الفقد هي تحذير `beforeunload` (`:~997–1004`).
**الأثر:** مستخدم غير تقني/مراهق قد يغلق التبويب أو ينقطع اتصاله فيفقد تعديلات جلسة كاملة. هذا "خسارة عمل" مباشرة.
**الإصلاح:** حفظ تلقائي دوري (مثلاً كل 20–30 ثانية عند `isDirty`) + مؤشر "تم الحفظ"، مع الحفاظ على زر الحفظ اليدوي.

### 🟠 متوسطة — عدم تطابق لغة المحتوى (SEO/ميتاداتا)
**المؤكد.** البنّاء يكتب `appearance.n` (مثال: `ThemeSettings.tsx` → `value={appearance.n || 'en'}` و`onChange` يسجّل المفتاح `'n'`)، وكل قارئ للقالب يقرأ `appearance.n` أيضًا (`ClassicTemplate.tsx:38`).
لكن ميتاداتا الصفحة العامة تقرأ مفتاحًا مختلفًا: `contentLocale` تقرأ `appearance['defaultLanguage']` (`src/app/u/[username]/page.tsx:49-51`).
**الأثر:** `og:locale` يظهر `en_US` دائمًا حتى للملفات العربية → ميتاداتا/مشاركة غير دقيقة.
**الإصلاح:** توحيد المفتاح (استخدام `n` في `contentLocale` أو ترحيل كتابة المفتاح).

### 🟠 متوسطة — صحة التحقق محدودة على حقول الملف
**المؤكد.** `updatePortfolio` يكتب `appearance` و`localized` و`contactLinks` **بدون أي تحقق** (`portfolio.ts:340`)، بينما يتحقق فقط من `sections`/`projects`. حقول `appearance` تُستخدم inline عبر `style` (React يُهرّب القيم، فالخطر منخفض)، لكن غياب المخطط يسمح بمفاتيح/قيم تعسّفية وتضخّم البيانات.
**الإصلاح:** مخطط zod لـ`appearance`/`localized`/`contactLinks` (نطاقات الألوان، أطوال النصوص، قائمة الخطوط المسموحة).

### 🟡 منخفضة — رابط خط بخطوط Google غير مقيّد
**المؤكد.** `fontLink` يُبنى بإدخال المستخدم: `` `...css2?family=${fontFam.replace(/ /g,'+')}...` `` (`ClassicTemplate.tsx:131`). النطاق ثابت (`fonts.googleapis.com`) فالأثر محدود، لكن قيمة `font` غير المسموحة قد تكسر العرض أو تُحمّل أوزانًا غير متوقعة.
**الإصلاح:** قائمة خطوط بيضاء (whitelist).

### 🟡 منخفضة — نطاق خاطئ في صورة OG
**المؤكد.** الصورة الديناميكية تطبع نطاقًا قديمًا في التذييل: `portholiohub.pages.dev` (`src/app/og/route.tsx:56`)، بينما الإنتاج `portfolio-hub.online`.
**الإصلاح:** استخدام `getAppUrl()` أو تحديث النص.

### 🟡 منخفضة (صيانة) — ملف البنّاء ضخم ومتضخّم المسؤوليات
**المؤكد.** `BuilderClient.tsx` = 3586 سطرًا، بأربعة `useEffect` فقط وكل منطق الصفحة داخله. يزيد تكلفة كل تعديل واحتمال الانحدار.

### 🟡 منخفضة (تجربة، مذكورة سابقًا) — فقدان بعض عناصر AR/EN وتحكم ناقص
**المؤكد.** توجد ثوابت قديمة `langMode='en'` / `showEn=true` / `showAr=false` (`BuilderClient.tsx:1222-1224`) بجانب الاعتماد الفعلي على `appearance.n`؛ تناقض يربك القراءة المستقبلية للكود. ومنطقة "التسجيل/تحرير الروابط الاجتماعية" (مثل `handleRemoveSocial`) تعدّل `profile.contactLinks` مباشرة (المسار القديم).

## 4) رحلة مستخدم عمره 17 سنة

1. يفتح البنّاء → الواجهة ضخمة (3586 سطر منطق) لكنها تعمل.
2. يعبث بالأقسام والألوان → **لا حفظ تلقائي**؛ إن نسي الحفظ وانتقل/أغلق تبويبًا يرى تحذير المتصفح فقط (`beforeunload`).
3. يحفظ يدويًا → `updatePortfolio` يتحقق من `sections/projects` فقط.
4. ينشر → `publishProfile` مجاني للجميع، بحدود أمان 30 قسمًا/50 مشروعًا/60 عنصر معرض (`portfolio.ts:578+`).
5. الخطر الأهم: أي مستخدم آخر — وليس هو — يمكنه استدعاء `updateProjectPage` بـ`id` صفحاته وتعديلها/حذفها (IDOR).

**الحكم:** المسار الأساسي **يعمل** لكنه هشّ في: حفظ العمل (لا autosave)، والأمان (IDOR + XSS محتمل)، واتساق اللغة.
